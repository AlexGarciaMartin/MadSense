Open architecture findings for root:
1. A failed virtual attachment left a live physical controller indefinitely stuck. Retry must include stalled/failed virtual creation, not only missing physical controller.
2. No controller should be a normal waiting state, not fatal startup. Background serialized worker should keep UI responsive through attach/dispose and retry.
3. Preserve raw default DualSense mapping. Bluetooth report31 payload copied to USB01 preserves physical trigger state echo (important to Stellar Blade), touch, sensors and timestamps. Remapping switches to synthesized input that intentionally lacks some echo/status fields.
4. HidHide blacklist membership alone does not prove active cloaking. Driver helper auto toggles global cloak; journal storing only a device ID cannot restore all prior global states. Preserve own changes and expose actionable failure instead of reporting ready if hiding failed.
5. Cleanup must isolate failures: controller disposal exception must not skip audio disposal and journal restoration.
6. Xbox360 mode skips HID discovery because the device is vendor-class. Existing Running status proves attachment request, not necessarily usable XInput. xusb22 driver-binding test exists; new XInput test adds real API verification.
7. Logs should be bounded and nonfatal. Existing portable logs/config beside EXE assume writable install directory. Rename changes HidHide whitelist executable path; add new path and avoid silently deleting unrelated entries.
8. One controller only; microphone physical Bluetooth capture absent; device firmware features mostly synthetic; physical unplug/reconnect, jack, touch and perceived latency remain distinct test gaps.

Compatibility / UX recommendation:
- Default native DualSense USB persona + automatic Bluetooth reconnection is a sound default for this project. Steam can translate that persona for games without native support when its per-game/global settings allow it.
- Label this 'Recomendado · DualSense + Steam', with helper explaining Steam Input configuration; 'Auto' alone misleadingly implies native support is universally detected by MadSense.
- Explicit 'DualSense directo' retains native capabilities; explicit 'Compatibilidad Xbox' covers XInput games outside Steam. Xbox provides sticks/buttons/ordinary vibration, not native adaptive triggers, touch coordinates, speaker or PS5 haptic waveforms. Game must implement advanced functions; its console origin is not the deciding factor.
- Do not change personality merely after detecting a running EXE; cached devices, player slots and games that do not hotplug can break. Do not publish both active personalities by default (double-input/player2 risk).
- Steam's 'Enabled in Games w/o Support' selective option is established, but exceptions and incorrect game metadata exist. Native games may require per-game Steam Input disabled. No supported public API found for external apps to atomically configure live Steam settings; do not edit opaque VDF files blindly.
- If adding game launch profiles later, select personality before launch, persist it per exact game executable, and offer explicit restart guidance for changes. Avoid claiming 100% compatibility or auto detection.

Recommended root regression sequence:
- No controller start, late wake, reconnect, DSX conflict, driver missing, failed virtual enumeration, pause/resume, repeated attach/detach, crash journal recovery.
- Native raw input/trigger status tests; physical calibration equality; active triggers while speaker+haptics continuously stream; very low amplitudes/silences.
- XInput driver bind + new API round trip; real game input and physical rumble are additional checks.
- Hide/minimize stops decorative animation; memory/CPU measured after warmup; closed-to-tray preserves connection, Quit cleans device.
- End-to-end latency needs hardware measurement. Host scheduling or polling interval is not total tactile latency and should be labeled accordingly.
